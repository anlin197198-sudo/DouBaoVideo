# F02 隔离恢复服务

2026-11-19 云端增量，基于 2026-11-18 V1.18 检查点。F02 继续部分完成，不改变整模块验收状态。

## 已实现

- 独立服务 `src/main/infrastructure/isolated-restore.ts`，必须显式传入当前工作区位置、解码器、源备份和目标父目录。调用者不能指定一个现成目录作为覆盖目标；每次用 `mkdtemp` 创建新的隐藏随机子目录，成功仅返回其位置。
- 每次重新完整验证源备份，不信任之前的验证报告。直接严格解析实际捕获的清单字节，并检查重复项、唯一数据库和文件白名单，避免清单在两次读取间替换后绕过路径校验。
- 仅复制清单列出的 `workspace.sqlite` 与 `media/references/UUID.png`，最后写清单。独占创建目标文件，分块读取、校验大小与 SHA-256 并同步写入；复验输出、源备份，再最终完整复验输出。
- 拒绝链接路径、源备份或当前工作区内部的目标父目录。写入前核对父目录与自有输出子目录身份，源文件打开后核对类型与身份；可用平台启用 no-follow/non-blocking 标志。
- 支持开始前和执行中的取消；同一服务实例拒绝重叠调用。失败仅清理身份确认属于本次的输出；输出身份异常时拒绝删除，返回明确的不完整输出错误。不同实例并发仍各自使用独占随机目录。
- V3/V4/V5/V6/V7 数据库原样复制，不迁移源或新副本，不写应用设置，不打开真实工作区数据库，不切换活动工作区。

## 安全和产品边界

目标父目录必须是用户可信、由本机控制的普通目录。路径和身份检查减少可检测的替换风险，但不是抵御同用户权限恶意进程持续竞争改写路径的操作系统沙箱；也不声称校验返回后文件不再可能被外部进程修改。

备份校验说明文件完整性，不证明备份来源真实可信，不保证全部业务语义或所有外部路径可用。业务数据库内保留普通账号资料和历史业务元数据，但没有应用会话目录、cookies、浏览器 profile、日志或视频文件。用户自己写入业务文本的秘密仍会随数据库复制。

当前已接入工作区信息中的恢复按钮与严格空参数 IPC，提供原生选源、先校验、选目标父目录、明确确认、只创建隔离副本的流程。确认默认取消，选源／选目标／确认时可退出；复制开始后界面提示等待完成，没有进行中取消按钮。确认绑定清单摘要，源内容变化拒绝操作，要求重新选择确认。没有 CLI、工作区切换、覆盖恢复或自动激活入口。只有服务成功返回才表示本次副本验证完成；异常或进程中断残留的隐藏目录不能据目录存在就当成可用恢复结果。此切片不提供断电恢复保证。

```sh
mkdir -p .local/restore-panel
npx --no-install esbuild tests/restore-panel.browser.tsx --bundle --platform=browser --jsx=automatic --outfile=.local/restore-panel/test.js
printf '<!doctype html><meta charset="utf-8"><script defer src="test.js"></script>' > .local/restore-panel/index.html
# 在浏览器中打开该 HTML，预期最终显示 PASS；FAIL 会包含原因。
```
