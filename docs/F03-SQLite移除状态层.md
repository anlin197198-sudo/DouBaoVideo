# F03 SQLite 账号移除状态层

V1.19 云端增量，基于 e5c569a。承接未接入的移除工作流；本轮仍没有产品移除按钮、写入IPC或真实Electron会话清理器，不执行真实账号移除。

## 持久化目标

V7 迁移保存账号移除状态、修订与排他清理标记，保留原账号行及任务、执行、成片引用。准备操作在SQLite立即事务内重新校验修订、关联执行及租约，只在安全时禁用并记录待清理。失败重试复用操作身份，但使用新的排他凭据；旧清理者不得完成或撤销较新操作。

已完成记录是唯一当前明确终态；其他关联执行状态保守阻止清理，不能把未知、失败或不确定直接视作可安全删除。现有登录打开与账号更新必须拒绝待清理／已移除账号，新派发及重分配不得进入该账号。历史执行记录本身仍保留并可按原身份查阅。

完成仅供工作流在清理验证后调用；数据库标记本身不能证明会话已删除。清理失败保持禁用及待处理，释放所属租约以便重试；完成后响应丢失也不能回退已移除状态。实际跨进程清理还须遵守排他凭据，持久状态层不能替代系统资源隔离。

## 崩溃边界

不设置超时自动抢占旧清理租约，不因进程重启自动把待清理账号变可用。残留租约可能需要单独的人工核验／恢复流程；这是故意的保守阻塞，避免仍存活的旧清理者与新会话并发。没有自称已经实现完整崩溃恢复。

## 未接入部分

真实分区清理与验证、现有账号窗口／网络句柄的安全关闭、用户明确确认UI、移除入口、状态解释界面及崩溃租约恢复仍待实现。现有打开动作开始后与准备操作交错的在途窗口，未来清理器仍必须关停并验证，不得以一次登录门禁替代完整会话排他。

## 验证

仅合成SQLite数据库、假清理器与测试账号ID，无真实会话或平台调用。新增 6 项合成回归，全量 `npm test` **147/147 通过，0 失败、0 跳过**；`npm run build`（含类型检查）及差异检查通过。覆盖两个 SQLite 连接依次竞争同一预览版本／租约轮换／旧租约拒绝、账号与执行变更使预览失效、登录与编辑／SQL分配门禁、事务失败回滚／重开、V6→V7数据保留及失败回滚、V7备份／隔离恢复保留待清理和已移除状态。旧V3／V4／V5／V6备份兼容回归保留。DatabaseSync 在同一JS线程中依次执行两个连接的事务，因此这里只证明跨连接CAS与持久租约，不是双进程同时争锁压力测试或真实清理进程验收。Windows、真实分区清理与用户验收未进行。
