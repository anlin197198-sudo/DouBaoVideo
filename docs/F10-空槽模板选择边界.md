# F10 空槽模板选择边界

## 当前不能直接接线的原因

现有正式提示词编辑通过 `PromptPanel.onChange` → `TaskCanvas.edit` → `WorkspaceAutosave.update`，修改后自动安排保存。把模板直接写入此路径会违反本轮「不自动保存」要求。不能为了按钮而暗改全局保存语义，因此本轮只实现内部文字选择边界，界面仍只复制，不增加填入或应用按钮。

未来若要安全填入，需要独立于工作区的可编辑缓冲区，明确展示范围及人工保存操作，并处理关闭、切换、修改期间的陈旧输入。这是产品交互改动，本轮不擅自实现。

## 内部选择不是采用

只允许镜头或首尾图位置，整条视频保持预览模式。仅当所选槽不存在或正文精确为空字符串时才可选择；空白文字也视为人工内容，不覆盖。输入必须明确接受并与此前预览的任务、修订、工作区、计划上下文及临时字段一致，保存中、脏稿、错误或冲突拒绝。

结构化临时字段齐全只能说明已提供对应字段，不能判断语义完整或提供方可用。没有关联人物、声音等可能是作者有意选择，不自动编造或将其变为必填。参考图上传对应关系仍未知时不能忽略该缺项。

成功仅返回所选文字，不返回被改写工作区，不执行 `editPrompt`，不保存、核对、确认或派发。所有其他提示词和人工内容保持。需要人工再次检查缺项及有效性；不能把成功状态当成自动生成、可提交或已完成的提示词。

## API 与校验范围

`TemplateDraftSelection` 捕获任务 ID、修订、工作区、计划、位置、全片及当前位置临时字段和保存状态。只有选定镜头／端点实际存在、结构化缺项已由明确字段填充且目标槽精确为空时，才产生 `structural-preview`。仍未提供的参考图上传对应关系会阻止选择；不把本地图片 ID 当上传位置。

`select(currentContext, true)` 再次格式化并比较完整上下文和文字，成功单次返回冻结的 `selected-text-only`，明确 `notApplied: true`。超出既有 10 万字符提示词上限拒绝，不截断；重复选择和同步重入拒绝。该上下文由内部调用方提供，不构成数据库并发锁或真实用户身份认证；未来接线仍需保存前复核。

即使结构化字段都有文字，画面、声音、关联资产仍可能有有意空项或语义不足。选择成功只表示确定选中了哪段文字，不是「内容完整」或「提示词完成」判定，不能绕过人工编辑与审核。

新增 4 项合成测试，全量 `npm test` 232/232（0 失败、0 跳过）、类型检查、生产构建及 `git diff --check` 通过。独立复审无阻断且定向 4/4 通过。覆盖精确空槽／手工空白、未知映射与缺项、无端点／视频、上下文变化、超长、重复选择及重入；没有新增 UI 或真实服务验收。既有第三方 `use no memo` 构建警告非阻断。
