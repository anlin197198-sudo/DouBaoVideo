# F03 本地账号移除：未接入的工作流边界

V1.19 首次云端基础切片，基于 f233947；本文保留首次切片证据，后续已实现的持久状态见 [SQLite移除状态层](F03-SQLite移除状态层.md)。产品要求移除时清理本机登录会话，同时保留历史任务、实际账号和成片关联；执行中可先停用，执行结束后再清理。

## 为什么不直接增加删除按钮

现有 AccountSessionManager 只有打开与关闭窗口，没有持久分区清理、验证或中断恢复。数据库没有持久移除状态，执行状态也没有已验收的完整终态枚举。直接删除账号行会破坏历史引用，直接把关闭窗口当作清除会话则是假成功。

因此本轮仅提供未接入的、可注入适配器测试的移除工作流边界。没有新的UI／IPC入口、数据库迁移或真实Electron清理适配器，不调用session分区，不访问真实账号，不修改现行账号资料。不能据本切片宣称“已能移除账号”。

## 必须保持的契约

- 预览具体账号与当前版本，明确本机会话清理、历史引用保留和不可再派发／登录的范围；用户明确确认后才能进入准备步骤。取消不改变账号。
- 正在执行、状态未知或无法确认安全终止的关联记录阻止清理；不能仅以字符串不在已知运行列表就当成已完成。
- 持久适配器必须在同一原子操作内复核预览版本、执行状态，并禁用账号、记录待清理标记；保留原账号ID／行和所有历史引用，不进行级联删除。
- 待清理期间所有打开账号、启用及派发路径必须检查持久标记并拒绝新动作，关闭现有窗口／网络写入后才清理指定分区。跨进程需真正的互斥与版本检查，不能只依赖单实例内存锁。
- 清理适配器必须可重试、幂等、仅作用于该账号，核验约定的数据范围后才报告完成；不得将“窗口关闭”“发起了清理Promise”当成清理成功。
- 清理失败时保持禁用／待处理；提交完成状态的响应不明时，持久状态可能已是 removed，必须核实，绝不回退 removed，不谎报已移除，不自动恢复为可用。重试保留原身份与引用，不扩展到其他账号。返回 pending 表示本流程未确认完成；完成响应丢失时，数据库可能已完成，必须由适配器核实，不能把该结果当作已读取的数据库状态。准备步骤失败直接抛错，不假称已经禁用或创建待清理记录。

## 首次独立切片范围与当时未完成项

服务通过注入契约验证顺序和失败处理；测试中的内存存储、清理函数只作用于合成数据，不是生产适配器。生产持久状态、跨进程互斥、调度／登录门禁、原生确认UI、Electron持久分区数据范围、清理验证及崩溃恢复仍待实现和验收。实际永久会话清理还需遵守当时用户确认，不因本开发任务取得真实账号删除授权。

## 验证

新增 6 项合成测试，覆盖确认取消、前后活动／未知阻止、过期版本拒绝、确认参数篡改隔离、清理失败重试、原身份与引用保留、同实例／跨实例竞争、完成或释放失败、完成已提交但响应丢失后幂等重试及清理结果作用域校验。全量 `npm test` **141/141 通过，0 失败、0 跳过**；`npm run build`（含类型检查）及差异检查通过。源代码检索确认没有主进程、UI或IPC接入此服务。Windows／Electron分区清理、真实登录与平台调用均未执行。备份、数据库版本和现有账户资料行为不改变。
