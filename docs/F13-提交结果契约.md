# F13 传输无关的本地提交结果契约

## 产品依据及范围

F13 要求保留同次提交的账号与请求信息，结果不明进入待核实；F16 要求恢复时先核实原请求，不能盲目重试。当前 `Execution` 只有通用状态及账号等字段，尚无足以证明远端受理的协议结果模型。本轮新增未接线的纯数据契约，不改变该持久化模型，也不发起任何提交。

## 同一次尝试的绑定

输入绑定本地尝试 ID、任务 ID、账号 ID、输入修订及输入快照 SHA256。摘要仅是调用方提供的绑定标识，本函数没有读取或证明实际图片、提示词或 F12 审核；不能凭摘要绕过提交前检查。

受理／拒绝证据必须来自未来可信协议适配器，且与全部绑定值一致。普通 HTTP 成功状态、超时、任意响应文字或调用方宣称成功均不能代替已验证协议证据。契约字段本身不是签名或身份认证，没有真实适配器时不能宣称官方已验证。

## 三类结果

- 已受理：仅已验证的受理确认及受限的远端定位身份；不是视频生成成功、可下载或完成。
- 已拒绝：协议明确证明没有创建远端任务；不能仅因错误、断网或没有响应就推断未创建。
- 待核实：缺失、超时、未知、格式错误或身份／输入不匹配；保留原尝试绑定，先核实原账号原请求。

每个结果的 `unconditionalRetry` 恒为 false，包括明确拒绝。是否创建新尝试、释放占用或继续派发必须由未来明确的工作流判断，不由此函数暗中触发。

## 不做的事情

这是无状态的单次证据判断，不是「最后响应覆盖前一次结果」状态机。迟到、冲突或多次证据的裁决及持久化归属需要另行设计，不能拿本函数当已经实现的恢复方案。

没有传输、客户端、队列、执行记录写入、UI、重试、查询或权限修改，不接受／回显任意异常原文、网址或路径。没有真实服务或密钥调用，DeepSeek 不参与；F13 真实视频业务仍为 L0。

新增 3 项合成回归，全量 `npm test` 244/244（0 失败、0 跳过）、类型检查、生产构建及 `git diff --check` 通过。独立复审无阻断、纯函数定向 3/3 通过。覆盖绑定字段逐项不匹配、协议证据缺失／超时／错误结构／远端身份格式、明确未建任务、恶意属性读取、结果冻结和所有分支不重试。没有真实平台或 UI 验收；既有第三方 `use no memo` 构建警告非阻断。
