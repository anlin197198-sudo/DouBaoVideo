# F17 V7 内部本地导入事务

## 实际可执行路径

`recorder.commitToWorkspace(database, capability, expectedIntent)` 是主进程内部入口。它只使用本 recorder 原始能力和冻结绑定，调用闭包中的物理验证函数，不接受调用者构造的“验证成功”对象。完整摘要检查在 SQLite 事务之外完成。

第一次有效提交尝试绑定实际 `ApplicationDatabase` 对象，之后不能拿该活跃能力切换到另一连接，包含重开同一路径的连接。未来宿主必须明确选择当前受管生产工作区；本轮没有自动识别“这个数据库曾经恢复过”的持久化 origin 标记，也不宣称仅凭 V7 内容就能识别工作区来源。

完成物理验证后进入短 `BEGIN IMMEDIATE` 事务，检查 V7、实际任务修订、权威现有成片版本、预期下一版本、execution／film ID 与命令请求号冲突。事务前后复核当前能力、归属和原始文件／父目录身份、大小及时间基线。同步最终文件检查后不再执行调用者 getter／归属回调，避免本函数内部可避免的重入窗口。

## 同一事务写入三类记录

- execution：新身份，operation=`local-import`，status=`recorded`，account 和 remote_reference 均为 NULL；input_json 仅固定来源、请求号、预期修订及指纹元数据。
- film：新 ID，绑定同任务、该中性 execution、实际版本及已验证的归档目标路径。没有保存原始选择文件路径。
- command_receipt：固定命令 `f17.local-import.record`、完整绑定哈希、固定规范 JSON 元数据和创建时间。不是 caller 提交的任意 JSON。

不更新 tasks 的状态、修订或制作内容，不把本地导入伪装成远程生成。不启用 UI、IPC、播放权限、调度器或默认启动流程。当前只读队列未为 `recorded` 增加展示语义，正式界面接线仍待后续设计；不要把它当已生成状态。

## 回放与失败

相同请求的元数据回放须同时匹配命令、哈希、规范结果 JSON、实际 film／execution 行和时间；输入改变或关联行被修改均拒绝。`readRecordedMetadata` 只报告既有记录，可在重开连接或隔离恢复后使用，但不创建能力、不验证视频现状、不授权再次写入或播放。

异常或条件失效返回 `recording-unconfirmed` 并禁止自动重试，不冒称数据库一定没有提交。所有代码都不会因取消、冲突、回滚或回执不确定而删除已归档文件。若需核对，使用严格只读元数据回放，不能自动重做文件发布。

内部 SQL helper 只是这个受信入口的实现依赖，不是可以单独暴露的授权接口。其参数不替代原始 capability 的验证，后续不得直接安装为 renderer IPC。

## 剩余边界

数据库事务不能原子锁住文件系统。大文件哈希不占用数据库事务；最终短身份／时间检查缩小间隔，但同用户恶意修改、文件系统 inode 重用、时间精度和崩溃耐久性仍遵循既有受信本地目录边界。没有 V8 迁移、跨工作区自动恢复授权、真实媒体完整解码或产品操作入口。

## 合成验证

真实 V7 临时数据库与真实暂存／独占归档测试覆盖：私有能力提交三行、任务完全不变、同请求不重复、改请求与仿造能力拒绝、过期修订／占用身份／冲突或异常版本／命令冲突、写入 command_receipt 失败整笔回滚、哈希期间撤销、归属回调改变文件时回滚及文件保留。

V7 备份→新隔离目录恢复保留实际中性记录及命令回执，但不包含视频，不激活工作区，不重建内存能力；只读回放可见历史记录，空登记表仍无法提供媒体。所有测试仅临时合成数据，未连接原生窗口或真实服务。

本轮新增 6 项事务／组合回归，全量 410/410（0 失败、0 跳过）、类型检查、构建及差异检查通过。独立静态审查无剩余阻断；未运行原生 Windows 或实际用户工作区。
