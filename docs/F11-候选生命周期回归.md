# F11 本地候选生命周期与归档修复

本轮对照 IMG 01 的独立首尾图、导入／替换及归档持久化要求，检查已有本地候选流程。不实现真实生图、账号调用或生成排队。

## 已发现的恢复反馈问题

画布记录图片加载失败后不再渲染该图片。重新导入相同图片虽然能修复归档，画布仍保留旧失败标记，直到整个任务重开。这是归档恢复后的预览反馈缺口，不是图片确认权限绕过。

本轮在成功导入后仅重置该图片的预览状态并请求重新加载。重新加载不等于已经验证显示成功，也不自动更换当前候选或确认图片；旧预览的迟到结果不能污染更新后的读取状态。导入时其他图片的失败状态保持。已有「重新检查图片文件」会对当前全部候选所引用的图片去重重新读取，画布与面板同步，不影响未列入检查的图片。资产参考图重导入同一归档也走对应图片的刷新。

## 候选与归档边界

- 同一归档图片可被两个独立角色候选引用，首尾选择按候选身份及角色隔离，不能将尾帧候选直接设为首帧。
- 移除未选中候选不会使当前审核失效；移除当前候选只清空对应位置并使旧审核失效。另一位置及候选来源内容保留。
- 移除候选只更新任务工作区，不物理删除归档文件；归档副本可继续复用或在缺失／损坏时通过重新导入原图修复。
- 未保存输入创建候选时不冒用旧提示词版本号。候选记录保留导入时文本与依赖快照，后续提示词编辑不回写该来源。
- 版本冲突不静默覆盖并发修改；未保存候选变动与文本继续留在草稿，必须按原冲突预览流程明确处理。
