# F17 本地导入与播放验收矩阵

本页区别云端已核实的能力与 Windows 必跑案例。F17 未完成。不要用真实豆包账号、用户素材或现有工作区做第一轮原生验收。

| 案例 | 目前证据 | 原生验收标准 |
| --- | --- | --- |
| 选择本地 MP4 与取消 | 注入测试覆盖取消、发起窗口失效、任务改版、资源关闭；未接成片页按钮 | 在成片所在任务明确选择源文件；取消不产生文件、导入历史或工作区修改；关闭窗口与切任务后不接受旧选择 |
| 文件安全与实际解码 | 固定只读源句柄核对身份、分块字节数与摘要；容器检查不证明可解码。合成 MP4 仅在 Linux 的 FFmpeg 解出全部帧 | 验证将保存的同一份字节确实在目标 Electron 呈现视频帧，有正确尺寸和有效时长；截断、无视频轨及不支持的编码不会登记成功 |
| 保存和重启 | 独占写入不覆盖；合成事务覆盖回执丢失，不自动重发。正式持久登记尚未接线 | 导入后重启，原任务与版本正确。两个同名任务产生不同文件；重做不覆盖旧版本。更改默认保存目录只影响新文件，旧文件仍从原位置播放 |
| 播放与定位 | 登记读流与单段范围用合成字节核对；现有成片页仅列版本 | 打开已登记版本，确认画面实际前进，暂停后可继续；跳到中段，画面及进度随新位置更新。切换版本或退出关闭旧流 |
| 文件移动及备份恢复 | 旧元数据不会自动获得播放权限；备份保留成片记录但不复制视频 | 文件移走时提示不可用，可显式重新定位或重新下载。恢复隔离副本不自动播放、重跑导入或借用原路径 |
| 失败与权限隔离 | 云端测试覆盖不确定发布、摘要不符、陈旧任务、未登记记录 | 可读错误提示不包含原始文件路径、账号或凭据；不确定操作仅核实同一次，不重放、不覆盖。明确测试 Windows 文件占用与长路径 |

第一轮在独立测试工作区生成一段短 H.264 MP4 和两份同名任务。Windows 启动的脚本与检查见 [隔离启动烟测](../packaging/Windows-隔离启动烟测.md)。Windows 安装和启动、原生导入播放以及真实豆包出片分别记录，任何一项不得作为另一项通过的依据。

### 首帧探测超时的区分

[视频帧回调规范](https://wicg.github.io/video-rvfc/) 要求视频帧实际进入合成流程；[Electron 窗口文档](https://www.electronjs.org/docs/latest/api/browser-window#page-visibility) 对初始隐藏窗口的绘制、可见性与后续隐藏有单独说明。原生测试须用同一合成 MP4、同一暂存来源，在准备使用的窗口和元素配置下观察。若超时，记录页面可见性、媒体错误分类、播放调用结果和是否收到帧回调，不记录路径或令牌；用可见窗口做对照，再区分绘制条件与解码故障。不得把单次超时或仅加载元数据判为可播放。
