# F08 离线资产候选契约

## 范围

对应产品 CAN 03 及界面「提取资产→检查建议→明确采用」流程，本切片仅提供内部结构校验和只读预览。没有真实提取器、提供方调用、UI、IPC、保存或采用方法，不能从一份剧本自动得到资产。DeepSeek 仍只用于 F07，不参与 F08。

输入只是明确提供的结构化 JSON 文本，按人物、场景、道具分组，保留名称与设定。候选键不是产品资产 ID，不分配资产身份，不生成参考图，不自动选择任何候选，不修改人工资产、关联、提示词或审核结果。

## 镜头关联的边界

只能通过输入显式给出的镜头 ID 对照当前任务镜头，存在与不存在的 ID 分别显示。不按标题、人物名、场景名、顺序或文本相似度猜测身份；一个候选可以对应多个显式镜头，未知身份不能静默删除，也不会形成实际关系。

现有模型中的场景是资产类型，并无独立场景实体。本轮不引入场景层级、场景 ID 或与既有人工资产的自动匹配。候选名字恰好与人工资产同名也不表示复用或覆盖；实际采用前仍需明确去重／合并／复用规则及可审阅的变化范围。

## 原文与预览生命周期

沿用 F07 内部边界：严格限长 JSON 文本，不清洗 Markdown、不执行属性或提供方指令。可接受大小内的解析／结构失败保留原文于实例私有内存，状态不泄漏正文或任意错误；非字符串与超限拒绝且不保留。

预览是冻结对象，只描述候选和镜头身份匹配，不是可执行补丁。当前性检查绑定原实例预览与完整工作区内容；有变化时需要重新预览。它不是数据库修订锁，无法发现内容 A→B→A 的历史变化，也不提供并发写入授权。丢弃实例会清理内部原文与预览索引，但无法撤回调用方已经持有的副本。

## 仍待实现

真实资产提取入口及费用／能力验证、用户可见候选版本与原文查看、人工资产去重和明确采用流程、采用后的安全身份分配及依赖更新、保存重开和真实桌面验收。本轮不提高自动提取 L0 的状态。

## 内部数据格式

`AssetCandidateSession` 接受最多 2 × 1024 × 1024 个 UTF-16 字符的字符串。严格结构为 `formatVersion: 1` 与必须存在的 `people`、`scenes`、`props` 三个数组；总候选最多 200，三个数组全空合法，不凭空补资产。

每项仅含 `key`、`name`、`description`、`shotIds`。键为 1–120 个 ASCII 字母、数字、下划线或连字符，跨组唯一，只用于候选识别；名字非空且最多 120 字符，设定最多 10000 字符。镜头 ID 为最多 200 个不重复 UUID；空数组表示未提供关联，不是自动关联。额外字段、重复键、非法 ID 等结构问题整体拒绝。

`preview` 将各组依次映射为 `person`、`scene`、`prop`，冻结候选内容与 `matchedShotIds`／`unmatchedShotIds`。这些只是匹配结果，没有关联写入；没有匹配的候选仍保留。`readRawReply` 只供未来明确的本地查看，`discard` 释放实例持有内容。
