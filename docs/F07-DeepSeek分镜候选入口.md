# F07：从已保存剧本生成分镜候选

## 已接入的首个流程

1. 剧本节点中，先保存正文，选择「生成分镜候选 · DeepSeek」。草稿未保存、保存中或冲突时不能发起。
2. 主进程从当前任务读取已保存的剧本和修订号。原生对话框列出任务和版本、接收方与可能的 API 费用，默认取消。渲染进程不能替用户提交确认，不能附带任意正文或参数。
3. 用户明确确认后再次检查保存版本，仅把剧本正文和固定分镜 JSON 指令交给 DeepSeek 文字策划适配器。不发送资产、提示词、图片、工作区路径或账号会话。若未配置适配器或密钥，退出并保留手动分镜。
4. 返回后重新检查保存版本。结构合法且版本仍匹配时显示按镜头位置的只读差异，不匹配则丢弃；当前编辑、镜头 ID、关联和历史不改变。原始回复不落盘、不进日志、不通过 IPC；格式错误可以手动重试。
5. 只允许一个生成请求在途，不自动重试；失败时已发送的请求仍可能计费。生成只是预览，未点击采用时不保存。
6. 仅在画布无未保存编辑、任务修订一致时可明确采用。空画布保留原直接采用流程。已有镜头时，候选必须按现有顺序逐项完全相同（名称、画面、动作、景别、运镜、对白或声音，空白也须一致），且在末尾还有至少一个新增镜头，才显示「追加新镜头为草稿」。任何差异、缩短、重排或无新增内容都仅供对照；不按名称猜测，不替换、移动、重建既有镜头或改其 ID 和资产关联。
7. 采用请求不接受渲染进程给出的正文。主进程以最长有效 10 分钟的一次性凭据重核任务、修订及已保存的原镜头 ID 和内容；新一轮生成使旧凭据失效。渲染端也核对本地草稿和原镜头前缀。仅追加段分配新 ID、标为待核对并填入编辑器，沿用常规修订与自动保存；采用命令不直接改数据库。

模型为 DeepSeek-V4.1-Flash-1017（官方托管调用名 `deepseek-flash`）；Doubao 生图／视频通道和原有安全门禁未改变。托管名是服务别名，不是硬件快照或永久版本锁定。

## 本地配置状态（非联网验证）

打开分镜策划区域仅通过受限 IPC 读取本地主进程状态，不发送剧本、不确认费用、不联系 DeepSeek。显示范围为已关闭、未检测到本地密钥、检测到本地配置（尚未验证密钥、联网或计费状态）；配置不可读取时仍可手动录入分镜。该检查不返回密钥、账号或服务响应。只有检测到本地配置且草稿已保存时才可手动点击生成，仍须完成独立的主进程发送确认。

## 面板与发送确认的生命周期

切换任务（即使修订号相同）、关闭节点详情、关闭候选、编辑状态变为不可用或保存版本调整时，旧候选／采用返回不会修改新草稿。原生发送对话框的肯定结果仅对发起时同一活动窗口及顶层文档有效；窗口替换、销毁、顶层重新加载或渲染进程退出后，不会据此发送。已发送的请求不会因关闭候选撤回；仅忽略其迟到结果。

## 自动验证与边界

用注入的合成回复测试真实命令路由、未保存的旧修订、缺少配置、取消、重复在途、发送前／返回后变更、结构失败、错误脱敏及未采用时无工作区写入。新增采用验证覆盖伪造、跨任务、重复采用和并发人工保存拒绝，字段、顺序及镜头 ID 保留；纯追加覆盖逐字段（含空白）差异、缩短或无新增、异步期间已保存版本变化、旧镜头位置及资产关联完整保留。Windows 原生对话框和真实账号／费用未实测；此阶段不使用任何真实剧本或密钥做联网联调。
