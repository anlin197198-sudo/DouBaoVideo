# F03 登录窗口生命周期保护

本轮承接 V7 移除状态层，依据 ACC 01 的独立登录会话及移除保留历史要求，只补充受管理窗口生命周期先决条件，不开放移除功能。

## 已知问题与修复范围

旧代码在 `loadURL` 等待期间，重复打开会直接显示正在加载的窗口；数据库门禁仅在服务命令开始时执行。账号在加载期间进入待移除状态，旧窗口没有加载后的再次核验。旧窗口迟到的关闭事件也可能误清除新窗口的登记。

本轮将生命周期抽成可注入边界：创建／加载、显示／聚焦与关闭以受管理窗口实例为范围，数据库状态在关键边界再次核验。生产登录使用此保护；不调用真实账号或访问平台进行测试。

## 栅栏与结果语义

- SQLite `BEGIN IMMEDIATE` 内检查状态并执行短同步窗口动作，不跨 `await` 持有事务。创建／启动加载和加载后显示分别检查 `present`，缺失或关闭的数据库保守拒绝。
- 同一账号加载中重复打开共用正在进行的加载，不提前显示；旧实例的迟到关闭事件不删除新实例登记。
- 单窗口移除前关闭要求当前 `pending` 状态、相同账号／操作身份及有效排他凭据。过期、释放或其他账号凭据不允许关闭窗口。此方法没有 UI／IPC 调用入口。
- 返回结果只声明本管理器拥有的该账号窗口已验证销毁，明确 `sessionCleared: false`。销毁异常或销毁状态无法确认时失败，不能回报成功；失效实例不得重新显示。
- 退出使管理器终止，未完成的加载不能在退出后重新显示窗口。

## 不代表完整移除

- 单个受管理窗口销毁，不证明 Chromium 会话、网络请求、服务工作线程或其他进程句柄已停止。
- 不清除磁盘分区、Cookies、登录凭据或远端账号，不提供移除 UI／IPC，也不接入移除工作流的真实清理器。
- 没有后台扫描或文件／数据库监控；待移除转换必须由未来协调器显式调用受限关闭步骤，不能只依赖打开时检查。
- SQLite 栅栏只覆盖遵守数据库事务约定的调用，不是操作系统级的全局排他。
- 真正移除仍需用户明确确认、可靠的全会话静止与清理验证、失败恢复及真实 Windows 验收。

## 验证

测试只使用假窗口、可控加载 Promise 和独立合成 SQLite。生产 Electron 登录窗口、真实账号隔离及系统会话清理均未运行验收。新增 7 项定向测试全部通过；全量 `npm test` 158/158（0 失败、0 跳过），`npm run typecheck`、`npm run build` 及 `git diff --check` 均通过。构建保留第三方 `use no memo` 非阻断警告。独立复审无新增阻断，并独立复跑定向 7/7。

覆盖重复打开共用加载；待移除／已移除时禁止创建或迟到显示；其他账号窗口不受影响；当前／错误／过期／释放／空租约；销毁拒绝或抛错不报告成功；旧实例迟到关闭／加载失败不能删除替代实例；初始加载失败可重试；无法验证关闭后禁止重显；退出后迟到完成不复活；数据库缺失／关闭时不执行窗口动作。可控 Promise 的交错不是实际多进程并发压力验收。
