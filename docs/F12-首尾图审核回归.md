# F12 首尾图审核回归与预览完整性

本轮依据产品文档 CAN 02／CAN 03、IMG 01／IMG 02，补充本地审核边界验证，不接入真实图片生成、视频提交或排队。

## 发现并修复的反馈缺口

原图片协议仅检查归档路径存在，再读取文件。已确认的归档图片如果被另一张仍可解码的 PNG 替换，预览加载可能成功，界面仍显示旧确认；专用确认命令则会因 SHA-256 不匹配拒绝。这是预览反馈与后端校验不一致，不是后端新确认绕过。

现在图片预览只返回与导入时记录的 SHA-256 一致的有界字节，协议直接使用这同一份数据，不在校验后重新按路径读取，响应禁止缓存。缺失、损坏或有效但内容不同的图片均不可预览，沿用界面已有的不可读／重新导入提示。重新导入原图可以修复归档。

## 保持不变的边界

- 首帧和尾帧按各自候选角色保存；替换一张不自动替换另一张。
- 当前图片、输入或参数改变使已有确认失效；改回旧输入也不自动恢复，必须再次明确确认。
- 图片归属本任务、候选来源不可改写、修订一致及提示词依赖核对仍由原保存／确认链保证。
- `hasCurrentConfirmation` 只判断已保存的逻辑输入，不能单独证明磁盘图片完整。历史确认记录不因图片文件不可读被抹去。
- 不新增后台文件监控。已显示在屏幕内的像素不会因外部文件修改自动刷新；下次读取／重新检查才重新验证。真实提交前还须重新核验实际提交快照，这仍未实现。
- 资产待核对提示不新增独立硬门禁；本轮沿用现有提示词输入核对规则，不擅自扩展产品要求。

## 自动化验证

使用独立临时 SQLite、真实编码的合成 PNG、生产命令路由和归档服务，覆盖不同颜色／比例的首尾图片、换图回退、持久重开、归档有效图替换／损坏与修复、陈旧提示词依赖。图片协议的纯响应边界单独测试；不把它算作原生 Electron 或浏览器验收。
