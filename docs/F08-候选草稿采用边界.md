# F08 候选草稿采用边界

## 为什么暂不新增界面

现行界面文档描述的是「提取结果→检查建议→采用资产与关联」，没有原始 JSON 粘贴工作流。真实资产提取器尚未确定，也不能使用只允许 F07 的 DeepSeek。因此本轮只补内部草稿应用边界，不新增粘贴页、生成入口、IPC 或提供方调用。

## 明确选择与保留

采用只接受本实例校验并预览过的候选，明确选中的候选键及确认操作。空选择不是全部采用。不按名称自动复用或合并，不覆盖人工资产、参考图、旧关联或提示词。选中项带有任何未匹配镜头时整批拒绝，不静默删掉关系；未选中候选不加入草稿。

仅追加新资产和明确匹配的镜头关联。新资产没有参考图，不可冒充已确认的出片素材。重复或含糊名称、容量不足、无效或冲突的新身份均拒绝。采用后只是本地工作区草稿，仍须走既有编辑／自动保存及修订冲突路径，没有直接写库或发送能力。

## 失效和重试

预览绑定任务身份、修订、工作区内容及有效计划上下文。未保存、保存中、冲突、保存错误、任务／修订／上下文或内容改变均不能使用旧预览。成功应用后不可再次使用同一令牌；取消或拒绝不修改工作区。此内存令牌不是持久化事务或产品级用户身份认证，未来界面必须由真实点击明确传入选择。

沿用现有镜头关联和确认失效逻辑，受影响镜头标为待核对，保留已有提示词正文和历史输入。未关联的新资产不凭空给镜头创建关系。

## 仍待实现

真实提取器、候选版本及原文呈现、用户可见的采用确认界面、与既有资产明确合并／复用的规则、保存重开及真实桌面交互验收。本轮不改变自动提取 L0，不代表资产能够自动生成或进入豆包提交。

## 内部约束

`AssetAdoptionSession` 从已有 `AssetCandidateSession` 及任务身份、修订、工作区和计划上下文创建预览。`apply` 要求当前上下文、保存状态、非空不重复 `selectedKeys` 和 `accepted: true`，以及调用方提供的新 UUID 工厂。采用名单明确，不默认全选。

为避免静默复用，名字用 NFKC、首尾去空白、连续空白合并和小写进行保守比较；与任一类型现有资产或同批候选重名均拒绝，原始显示名称不改写。这只是歧义门禁，不是自动合并规则。总资产数量必须符合既有 200 项上限。新 UUID 必须合法并不与当前任务、镜头、资产、图片或相关节点身份冲突；全部身份检查成功之后才构造结果。

采用返回的草稿依然包含原提示词正文及旧快照；受新增关系影响的镜头标为待核对，并按现有确认输入变化规则失效。没有增加任何资产图片或出片确认。失败可能消耗调用方的 UUID 工厂序列，但不会保存、修改原工作区或返回部分采用结果。

新增 4 项合成测试，全量 `npm test` 215/215（0 失败、0 跳过）、类型检查、生产构建及 `git diff --check` 通过。独立复审发现并修复 UUID 工厂同步重入问题，最终独立定向 4/4 通过、无阻断。既有 `use no memo` 第三方构建警告非阻断；没有 UI／Windows／真实提供方验收。

执行期间拒绝同步重入；身份工厂返回后重新核对完整输入与来源状态。回调期间变更接受意图、选择、任务修订、计划、保存状态或工作区，以及丢弃来源候选，均不能继续应用。测试涵盖保留内容、明确选择、失效与保存门禁、重复名称／容量／身份、重复应用和回调变化。
