# F10 明确写入空白提示词

本轮新增独立的明确动作，将临时编辑区文字写入选定的空白镜头／首帧／尾帧提示词。按钮及说明直接告知：写入后进入现有自动保存。它与临时输入、恢复和复制分开；仅操作临时编辑区仍不会写入项目。

## 写入门禁

写入前必须核对任务、所选槽位、修订、工作区、计划上下文、准备来源与缓冲区轮次。画布端还使用自动保存控制器的最新内容及状态再次检查，不能只信任旧组件回调。未保存、保存中、冲突或错误时不写入；目标必须不存在或正文精确为空，人工空白也不覆盖。

只写入明确选中的槽位，文字非空且不超过现有限长。来源变化必须重新准备，不能把旧临时文字静默用于新任务或新端点。整条视频不开放写入，因为当前临时字段还未支持完整逐镜头汇集。

## 保存和确认语义

明确写入成功仅代表工作区草稿更新，并不代表已保存成功。之后由既有自动保存／修订冲突路径负责；失败仍保留草稿，使用现有重试及冲突界面。普通保存可追加版本历史，不覆盖旧历史。

使用现有单槽 `editPrompt` 及依赖／图片确认失效逻辑，不调用「已核对」操作，不自动确认任何图片或素材。其他提示词、手工内容、布局和关联保持。成功后退出本次临时缓冲区，不能重复应用同一轮次。

无外部模型、DeepSeek、账户、网络请求、权限修改或视频提交。真实提供方和 Windows 验收仍不在本轮范围。

## 实现和回归

缓冲区捕获不可变轮次／文字／来源信封，组件使用当前 ref，画布专用回调再以实时控制器值校验。保存状态仅比较 dirty／saving／error／conflict，诊断 requestId 不参与内容身份，避免无关诊断字段导致错误失效。来源或轮次不一致时不清空临时内容。

新增合成测试覆盖只写所选槽、保留其他文字和旧输入快照、重复／陈旧／跨上下文／占用与保存状态阻断、现有空记录不自动核对、确认失效。通过真实 SQLite 和普通自动保存路径验证首次保存失败仍保留草稿，重试成功追加历史，关闭重开后旧历史仍在。

新增 3 项合成回归，最终全量 `npm test` 238/238（0 失败、0 跳过）、类型检查、生产构建和 `git diff --check` 通过。独立静态复审无阻断，独立纯函数 2/2 通过；文件集成测试未由审查者单独运行。确认失效断言使用合成确认记录，不是实际图片审核验收。真实 UI／Windows 未运行；既有第三方 `use no memo` 构建警告非阻断。
