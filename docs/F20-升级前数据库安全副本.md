# F20 升级前数据库安全副本

对照《功能开发文档》F20「升级前保留可恢复的数据库副本，迁移后检查版本和关键记录」。此切片接在 Electron 单实例锁后、主窗口与工作区服务打开前。仅适用于应用自己管理的私有本地工作区；升级期间不得由其他进程写入。不会接收任意目录或外部数据库，也不执行恢复。

- 新工作区仅在数据库与 SQLite 附属文件都不存在时直接初始化。现有 V7 数据库通过只读版本和已知结构辨认后无需制作升级副本。仅识别结构匹配的 V1–V6 为受支持历史版本；保守阻止既有 V0、未知结构、损坏、重定向和较新版本，不尝试降级。
- 已知旧版：只读建立源连接，预先检查完整性、外键和关键表记录数量。SQLite 在线备份包括已提交 WAL 数据，不把复制主数据库文件当作备份。
- 副本在同一私有工作区的 `upgrade-backups/before-vN-<随机名>/workspace.sqlite`；文件独占创建，不覆盖。只对副本切换至独立的 DELETE 日志方式，再以只读连接检查快照结构、版本、完整性、外键和关键表数量，并确认不依赖 WAL 等附属文件。校验触发的 SQLite 正常锁／共享内存操作不承诺整个目录零变化。
- 副本同步、记录 SHA-256／字节数、复查源变化信号后，才写入独占的 `verified.json`，随后开始迁移。迁移后检查当前目标结构、版本、原有关键表记录数、完整性与外键。写入有异常时阻止升级；若升级已开始但失败，保留原版本的验证副本和可能已发生的部分迁移，**不回滚覆盖、不自动恢复**。失败生成的临时内容可能保留，不应据路径名或单独的标记存在就信任；手工处置前需重新核对标记、哈希、版本、文件完整性。
- 这是数据库快照（包含业务表、业务文本、账户元数据等原有数据库内容），并非 F02 业务备份格式，不包含图片、视频、浏览器分区和外部凭据，也不复制这些目录。用户自行写入 SQL 业务内容的秘密不会被脱敏；不要分享副本。未实现应用内恢复或自动清理。
- 不宣称抵御具有同一用户权限的恶意目录修改、并行写者在复核之后的写入、机器突然断电或文件系统不提供的持久性；也不保证所有历史业务数据均能迁移。现有多阶段迁移可能在失败前已提交较低版本。

独立合成目录覆盖 V1/V2/V3/V4/V5/V6→V7，真实 WAL-only 记录，已最新不重复备份，失败保留 V4 快照且原库停在 V5，复制错误／行数不符／源提交，各种不支持的旧库或重定向、标记冲突。不使用真实账号或业务资料。云端 Node 回归不代表 Windows 应用运行、安装升级实测，也不改变 F20 整体状态。
