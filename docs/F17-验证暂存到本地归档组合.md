# F17 验证暂存到本地归档的主进程组合

## 已连接的真实模块

新增 `createVerifiedLocalImport`，仅供可信主进程显式调用：

1. 冻结规范导入意图，核对输入摘要、实际任务修订、下一成片版本及 ID／请求冲突。
2. 意图中的 owner 必须精确等于本次实际私有 decoder 窗口／文档身份；不接受在一个窗口探测后绑定到另一个 owner。独立 `isCurrent` 是发起任务的当前租约，不是已关闭 decoder 的存活检查，须由宿主保证。
3. 使用已有准备器暂存并签发该 owner 的受限能力，取得合法首帧报告且确实读取过该暂存字节。
4. 撤销能力、取消探测并等待明确的原生停止确认。
5. 将同一暂存读取器交给真实独占归档及私有 recorder。没有重新读取原始选择文件，也没有可注入“写入成功”替身。
6. 物理复核成功后进入既有 V7 事务，原子记录中性本地 execution、film、command_receipt。任务状态／修订／制作内容不变。
7. 等待归档、SQL及所有取得中的来源／读取器结束，再清理本次暂存和 intake。

没有 UI、IPC、默认启动入口、播放授权或服务请求。本轮集成测试的原生宿主是明确注入的假对象；文件写入、字节验证和 SQLite 则是真实临时实现。

## 独立副作用移交，不改变只读契约

准备器第四参数 `SnapshotHandoff.consume` 仍是只读、可与取消竞争的消费模式。新增第五参数 `SnapshotEffect` 必须显式选择 `mode:'await-settlement'`，两种模式不能同时使用，而且副作用模式必须有明确 stopProbe。

副作用回调不能因取消抢先返回并遗留后台工作。准备器等待回调结算，跟踪尚未完成的来源取得并关闭读取器后才允许 discard。回调拒绝只意味着结果未确认，不意味着没有发生写入。该契约适用于受信端口；不能把任意不会结算的后台任务塞入其中。

字节总量沿用既有限额和流式读取，不全片聚合进内存。此阶段不声称文件系统 I/O 有硬性墙钟上限，不会用强制超时删除仍被副作用持有的暂存。

## 事实分层与取消

结果分别保留 preparation、archive 和 record，`settled` 只表示这次组合已结算，不是“导入成功”的别名。

- 发布前取消或归属失效不能开始归档。
- 发布后、数据库前取消：保存实际发布回执和文件，record 为空，不自动重试或删文件。
- SQL 回滚／未确认：归档文件与其回执保留，数据库结果独立报告。
- 数据库已经记录后出现 intake／暂存清理失败：保留 `recorded` 的事实，同时明确 cleanup-unconfirmed，不能伪装整件事没有发生。
- 原生停止未确认：没有进入归档／SQL，保留未确认暂存。
- 相同有效请求再次调用只回放严格元数据，不重复探测、发布或覆盖已有文件。

私有 recorder 会在组合结束后关闭。恢复后的普通记录不重建它，不能自动再次归档或执行。

## 与远程生成恢复的区别

本功能是独立本地附件归档，保留任务状态和本地来源，不借用远程 execution。

PRD RUN 02 中“已经生成但待下载”的恢复仍是另一个未实现路径：必须使用原远程 execution，并明确核验为同一次生成输出，不得重新提交。当前 local-import 不能代替该恢复，也不能据此宣称豆包下载、远程恢复或生成链路完成。本轮不改写 PRD。

## 验证

合成回归覆盖完整顺序与精确字节、重复不覆盖、实际发布后取消而无 SQL、失败首帧／停止失败／修订漂移不发布、SQL 回滚、记录后清理失败保持事实，以及 owner 不匹配时零 probe／stage／archive／DB。底层移交回归验证晚取消不会在回调结算前删除暂存、拒绝仍报告未知、最终租约回调取消保留已发生结果。

同一个组合实例串行使用其专属 decoder 生命周期；并发请求被拒绝，不关闭正在处理的同一 intake。未来不同导入需要由宿主创建正确的新私有窗口／文档，不能复用已失效的解码文档。

本轮新增 9 项回归，全量 419/419（0 失败、0 跳过）、类型检查、构建及差异检查通过。原生行为仅假宿主注入，真实临时文件与 SQLite 组合通过；没有 Windows／豆包验收。
