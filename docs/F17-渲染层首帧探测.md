# F17 渲染层首帧探测（内部、未接线）

基线 `993b021`。新增渲染层独立首帧探测器，不挂接界面、注册表、应用协议、真实文件或主进程。它本身不创建套接字，不调用 fetch，也不接受普通磁盘路径或外链；只接受与既有主进程范围契约一致的 `app://video/<小写UUID>` 确切形式，拒绝编码变体、附加路径、查询、片段、凭据及端口。格式合法不等于授权成功；仍须由未来主进程登记与协议层核验媒体许可、句柄及范围读取。

- 用新建且不插入 DOM 的 `video`，不显示播放器或控件，禁用 autoplay、循环、远程播放、画中画；静音并明确调用 `play()`。
- 元数据、`play()` 成功、`playing` 均不是验证通过。只有 `requestVideoFrameCallback` 发出首个有效画面，对有限正时长、固有视频尺寸、解码帧尺寸、时间与已呈现帧数量校验后才接受。
- 默认期限 4 秒、最大 10 秒；支持传入 `AbortSignal` 取消。超时、取消、媒体出错、无法播放、无帧回调能力或帧证据不完整一律失败，不降级为元数据通过。所有已取得视频实例的终点都会解除监听与回调、暂停、移除源、调用 `load()` 停止，清理为逐项尽力且不因单个异常短路。迟到事件不会改写结果。清理只释放探测器持有的元素和读取，不等于撤销主进程的能力许可。
- 成功表示至少观察到客户端提交的一个有效画面，不验证后续帧、跳转、音频、整文件完整性、解码兼容矩阵或播放终点。

自动测试使用注入的模拟视频元素，覆盖成功、地址拒绝、元数据不足、超时和取消、解码帧证据不足、播放错误与释放。尚未运行 Windows、Electron 或真实媒体。尤其需用生产协议、合成媒体及目标环境确认离屏元素能收到帧回调；如果没有回调，该路径会超时且仍未验收。
