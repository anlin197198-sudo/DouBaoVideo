# F07 内部离线分镜候选契约

本轮依据 F07 的有序镜头、解析失败保留原回复及再次生成先比较候选要求，实现可测试的内部数据边界。不调用模型或网站，不读取真实剧本，不增加 UI、IPC、采用按钮或自动写入。

## 输入

只接收 JSON 文本字符串，不接收任意 JavaScript 对象，也不猜测自然语言、Markdown 或围栏中的内容。调用方须显式提供 `{ "formatVersion": 1, "shots": [...] }` 的 JSON 文本。字段全部明确，未知字段、错误类型及不合法顺序拒绝，不默默丢弃或修正。

输入最多 2 Mi 个 JavaScript 字符单位（不是字节限制），镜头数量 1–200。超限不进入会话，也不宣称保存了超限原文。正常接收的原始文本发生 JSON 解析或结构验证失败时，完整保留在会话私有内存，以便未来明确重新整理；错误结果不回显原文，不写日志或磁盘。丢弃会话释放该原文。进程退出后不恢复，不是持久候选历史。

| 输入字段 | 内部候选字段 | 规则 |
| --- | --- | --- |
| order | order | 数组中必须依次为 1..N，不按值猜测或重排 |
| title | title | 明确提供镜头标题 |
| visual | description | 画面描述原文 |
| action | action | 动作原文 |
| framing | shotSize | 景别原文 |
| motion | cameraMovement | 运镜原文 |
| dialogue | audio | 对白或旁白原文，沿用现有单一音频文本字段，不拆分或生成 |

正文与短字段沿用当前镜头模型的长度边界，不转换类型、不翻译、不自动生成内容。内部候选没有现有镜头 ID 或画布位置，也不是可直接写入工作区的对象。

## 预览与现有编辑保护

按镜头位置提供当前稿和候选的字段变化范围，能指出新增、移除或字段不同。位置比较仅供阅读，不表示两个镜头具有相同身份，也不能直接作为合并补丁。

记录比较时工作区内容，当前内容不一致时旧预览不再匹配，需要重新检查。`isCurrent` 仅比较完整工作区 JSON 内容并核对预览属于当前会话；不是单调版本号或并发授权，也不能检测已改动后完全还原的编辑历史。后续真正采用必须另接明确确认和服务端修订门禁。原工作区、镜头身份、资产关联、提示词、布局和图片确认不被此接口修改。没有采用或保存操作，更不会自动重新确认下游。

## 验证及后续

实现为 [StoryboardCandidateSession](../src/shared/storyboard-candidate.ts)：
- `status` 只返回固定状态／错误类别及是否保留原文。
- `readRawReply()` 为内部显式读取；完整原文位于 ECMAScript 私有字段，不随会话或错误 JSON 序列化输出。成功接收的原文也只存在此内存范围。
- `preview(workspace)` 返回冻结的按序差异；`isCurrent(preview, workspace)` 检查内容快照；`discard()` 清除内部原文和候选，并使原预览凭据失效。已交给调用方的预览内容不会被反向擦除。
- 没有采用方法，也没有接入生产命令、界面或数据库。标题≤120、画面／动作／对白≤10000、景别≤120、运镜≤500，与当前保存模型的字段上限一致。

新增 [4 项合成测试](../tests/storyboard-candidate.test.ts)，定向 4/4，全量 `npm test` 174/174（0 失败、0 跳过）；类型检查、生产构建和 `git diff --check` 通过。覆盖字段映射、无生产ID、不改现有稿、JSON／结构／未知字段／缺失字段／版本／顺序失败、原文私有保留与丢弃、所有字段与数量／输入大小边界、不调用对象getter/toJSON、只读按序差异和过期检查。独立审查及定向 4/4 通过。构建保留既有第三方 `use no memo` 非阻断警告。
