# F17 私有探测页与媒体同会话路由

## 本轮实际实现

扩展已有私有 `app` handler，不再要求页面和视频各注册一个相互冲突的 handler。仍然只在宿主提供的独占非持久化会话中注册，固定绑定主进程确认的窗口／文档 owner，不从请求推断身份。

可注入可信构建资源加载器，接收只含 URL／method 的请求副本。分派器仅允许 GET／HEAD 的固定 `app://video-probe/f17-video-probe.html` 和 `/assets/` 下单层安全文件名 `.js` 路由；无查询、片段、任意子目录、其他主机或网络回退。加载器必须进一步核验构建清单、内容及响应头，不能把正则允许的文件名直接当任意磁盘读取权限。未注入时保持原有仅视频行为。

`app://video/<规范UUID>` 继续交给已有能力注册表，按固定 owner 验证有效期、来源及字节绑定。页面 URL 的片段在浏览器资源请求中通常不存在，路由不会把片段当窗口身份或媒体许可。

## 异步与清理

页面和媒体请求均在调用前、异步返回后复核独占绑定及活动状态。所有权失效或 teardown 后才返回的资源正文会取消，不交付。保留先失效 owner 能力、再注销单个 handler 的顺序及清理失败报告。已交付流不在此处强制撤回。

## 剩余接线

本模块未被应用入口启用，没有修改全局 scheme 权限或默认 Session。后续宿主需把经清单验证的构建资源加载器传入该适配器，再由专用窗口工厂在加载前安装；还需绑定媒体能力、原生页面结果采集及安全的 CSP／资源策略。没有运行 Electron 窗口或 Windows 解码验收。

## 验证

新增 3 项合成回归：同一 handler 分派页面／JS／视频、可选加载器及固定错误拒绝、加载中失去所有权或 teardown 时取消正文。相关测试 7/7；全量 368/368（0 失败、0 跳过）、类型检查、构建及差异检查通过。没有运行原生协议或实际解码。
