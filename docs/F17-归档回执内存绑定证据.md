# F17 归档回执的内存绑定证据

## 本轮没有写入 V7 业务表

现有独占写入回执只含发布状态、目标路径和临时清理结果，没有绑定请求号、任务修订、归档身份及摘要。把它与另一组调用者字段拼接，不能证明是同一次写入。因此本轮不据此插入 execution／film／command_receipt，也不发明本地导入的业务状态，不修改任务状态或迁移数据库。

## 已实现的先决条件

主进程 `createBoundArchiveRecorder` 每个实例只允许一次尝试。它先严格解析并冻结请求号、film/task/execution 身份、预期任务修订、版本、标题、显式目录、可信宿主提供的 owner 标签及字节数／SHA-256，再直接调用真正的 `archiveStagedVideo`。没有可替换的“成功写入器”参数。

只有完整字节独占发布、临时与源读取清理确认、返回时归属仍有效、目标名称严格匹配时，才创建一个冻结的内存能力对象。私有 WeakMap 记录该对象对应的原始请求及其稳定哈希。它不是在普通 JSON 回执上附加调用者字段。

检查必须持有原始对象并提供完全相同的绑定。复制、序列化再还原、换请求／任务／修订／版本／目录／摘要／owner，或来自另一 recorder 的对象均不能取得证据。实例关闭、显式撤销及已观察到的归属失效均不能恢复权限。取消、未知或不完整发布不生成证据；但实际写入回执仍原样保留，晚取消不删除或隐藏已发布文件。

## 证据不是持久化授权

返回项明确标注 `physicalFileRechecked:false`、`writeAuthorized:false`、`databaseCompleted:false` 和 `mediaPlaybackAuthorized:false`。这只说明本进程曾观察到与这些输入对应的字节发布，不证明文件现在仍相同，也不证明原生解码、真实 task revision 或版本预留。owner 归属检查仍须由可信宿主提供，不能拿 renderer 声明替代。

内存对象不能跨进程／重启／备份序列化成权限。未来 SQL 端口仍需：重新固定并核验实际目标文件、在同一事务检查权威任务修订与版本、定义中性本地导入身份及命令幂等回执、处理已经发布但数据库失败的情况。数据库失败不得删除可能已经发布的文件。当前只读 handoff 仍不能承载这个写入副作用。

## 验证与备份边界

合成测试使用真实 intake、暂存、独占归档及 V7 SQLite，比较所有业务表快照确认没有任何写入；覆盖真实对象与仿造／跨实例／替换绑定、取消与占用目标、发布后失效、输入冻结及失效不可复活。只使用临时合成 MP4 和合成任务。

没有改变 V7 schema、备份或隔离恢复格式。既有成片元数据备份／恢复回归继续验证：只保留历史记录，不复制视频或登记读取能力，不启用执行；新的 WeakMap 对象根本不进入备份。普通回执 JSON 与恢复后的路径不能重建本轮能力。

本轮新增 4 项回归，含 getter／归属回调中同步撤销、关闭和取消的重入场景。全量 400/400（0 失败、0 跳过）、类型检查、构建及差异检查通过，包括既有 V7 成片元数据隔离恢复测试。独立静态审查无剩余阻断；未运行原生窗口或数据库写入端口。

后续已增加能力限定的 `verifyPhysical`，可根据原始发布身份重新验证实际文件；普通 `inspect` 仍不宣称物理复检，且两者均不授权数据库写入。见 [物理复核边界](F17-绑定归档文件物理复核.md)。
