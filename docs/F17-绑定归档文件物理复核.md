# F17 绑定归档文件的物理复核

## 原始身份不能事后补造

独占写入器现在只在干净、确定发布后附带冻结的 `publishedIdentity`。device／inode 来自它创建并持有的原始临时文件和最初确认的父目录，不是事后从一个同名路径猜出来。自身临时链接清理后，还核对目标为同一个普通文件、单链接、预期大小，并记录 size／mtimeMs／ctimeMs 基线。未知、非安全整数或零 inode 等不可靠身份不提供证据。

如果清理后基线不能取得或已变化，仍保留“曾确认发布”的真实回执，只省略物理证据。不能把它改成未写入并自动重试。

## 私有能力限定的验证入口

`recorder.verifyPhysical(capability, expectedIntent)` 只接受本 recorder 原先颁发的能力对象与相同预期绑定，没有任意路径验证参数。复制、跨实例或撤销对象、换绑定与失效归属均失败。缺少原始发布身份也失败，不能用补填字段升级普通回执。

验证使用绑定目录和确定性文件名，先比较原始目录及发布后文件属性，再复用受限登记读取器：重新打开只读固定文件句柄，拒绝符号链接／多链接／非普通文件，核对原始 device／inode 和精确字节数，按 64KiB 块计算完整 SHA-256，前后复核句柄及路径。取得成功后明确关闭来源，再复核父目录、文件基线及能力归属；不把文件句柄或媒体流交给外部。

成功结果只表示此次物理观察通过，仍为 `writeAuthorized:false`、`databaseCompleted:false`、`mediaPlaybackAuthorized:false`。它不执行 SQL，不更改任务，不登记播放器权限。

## 威胁模型与下一步

相同内容的新 inode 不是原始发布，必须拒绝。原地同尺寸篡改、原路径缺失／变成链接、异步验证期间失效也不能成功。

受信本地目录与正常文件系统语义是前提，不声称抵御同用户任意篡改、恶意文件系统或所有 Windows 重解析点。device／inode 可能被文件系统重用，毫秒时间戳也有精度限制；附加时间和大小基线降低误认，但不是不可复制的硬件身份。验证关闭句柄后文件仍可能改变。未来数据库阶段必须有明确的时序、重新检查和事务契约，不能把本次结果长期保存成免检授权。

本轮没有原生 Windows／播放器验收、数据库迁移、启动入口或 renderer API。

## 验证

临时合成文件及 V7 数据库回归覆盖原始发布成功、同尺寸篡改、保留旧文件后用完全相同字节创建新 inode、缺失、符号链接、验证途中撤销／关闭／归属改变、复制及错误绑定拒绝，并比较所有业务表未变化。原始写入器测试对照真实文件和父目录属性，清理后目标改变时仅省略证据。

本轮新增 4 项回归；定向 11/11、全量 404/404（0 失败、0 跳过）、类型检查、构建及差异检查通过。独立静态审查无阻断，未运行原生窗口／Windows 文件系统验收。
