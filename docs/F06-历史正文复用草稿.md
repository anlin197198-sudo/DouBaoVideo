# F06 历史正文复用草稿边界

现行剧本历史界面保持只读。本轮未新增恢复按钮、原文粘贴入口或 IPC；只补内部按任务读取历史、明确预览与复用为新草稿的服务边界。不调用 AI 或 DeepSeek，不生成新剧本。

## 原文来源和确认

预览由应用数据库中指定任务的指定历史版本读取，不接受调用方拼接的“历史正文”。同时绑定当前已保存任务修订、工作区与计划上下文。冻结预览包含所选历史正文及当前正文供明确比较，不修改任何数据。

采用必须显式接受同一实例的原预览，且本地没有未保存、保存中、错误或冲突。任务、修订、工作区和计划上下文变化时拒绝；再次核对当前数据库和历史来源。外部复制对象或其他实例预览不能代替原预览。成功只返回新草稿，单次消费，不直接保存，也不创建新版本记录。

## 保留与失效

替换仅作用于剧本正文，保持布局、镜头、资产、关联及原提示词文字；沿用现有 `editScript` 将依赖标记待核对，并按现有规则使受影响的 F12 确认失效。既有历史正文及当前已保存正文直到普通保存成功之前均保持。

调用方后续必须走既有自动保存／修订冲突路径，正文确有变化时追加新的历史版本，不改写旧版本。复用空正文仍是明确选择，可能产生清空草稿；同正文是无变化，不虚构一个新的历史版本。未记录的旧状态不能凭此恢复。

本地草稿应用不是已保存成功、视频素材确认或发送授权。关闭或重启之前若没有保存，仍遵循现有未保存草稿处理，服务不增加隐藏持久化。未来用户界面还需明确展示替换范围、空正文提示、保存失败和关闭／切任务处理，再完成真实桌面验收。

## 内部接口

`ScriptReuseService.preview({taskId, expectedRevision, historyVersion})` 通过任务限定的仓库读取，返回冻结的 `draft-preview`：任务修订、当前正文、历史版本元数据及正文、是否确有变化。错误只返回固定原因，不输出任意异常或数据库细节。

`apply(preview, {taskId, revision, workspace, planStyle, saveState, accepted})` 在同步事务中重读并比较当前保存状态及历史，构造独立副本；结果为 `draft-applied` 或 `no-change`，不表示已保存。成功后同预览不能重复采用；执行锁阻止同步重入。计划上下文按风格及备注规范化比较，改变继承来源同样使旧预览失效。

新增 4 项合成 SQLite／PNG 回归，全量 `npm test` 219/219（0 失败、0 跳过）、类型检查、生产构建及 `git diff --check` 通过。测试覆盖真实本地两图确认后的失效、普通保存追加新历史与关库重开、旧版本保持、实际并发保存阻断、空正文与同文、伪造／跨任务／实例和保存状态门禁。未做真实 UI／Windows 验收；既有第三方 `use no memo` 构建警告非阻断。

独立静态复审无阻断；审查者未独立运行文件测试。
