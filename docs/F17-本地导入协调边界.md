# F17 本地导入协调边界（离线、未接产品）

本切片只协调主进程受信端口，不增加数据库表、迁移、IPC、选择器、界面、解码器或文件操作。用于测试“选择、预留、暂存、验证、独占发布、最终提交”顺序，不能从端口模拟成功推导真实 MP4 可播放。

## 顺序与安全要求

- 协调器接收主进程已完成选择和确认的意图，或代表初始取消的 null；null 不调用端口。真实选择器／确认界面仍未实现。用户选择取消必须发生在预留和写入之前。导入预留是独立操作，不借用真实生成执行，不将任务或远端执行标为完成。
- 暂存副本绑定本次操作和预期字节长度／摘要；只有同一副本的明确正向解码证据才能继续。文件扩展名、容器标记、摘要匹配不能替代实际解码。
- 发布前核对同一意图仍有效。端口还必须在异步发布期间持有有效排他权限，前后检查本身不是文件系统事务。
- 发布必须独占且不覆盖。发布不确定或最终提交回执不确定时进入核实，不自动再次发布或生成新版本。
- 最终提交须比较同一预留及输入，原子写入真正的媒体登记／归档记录；数据库持久实现尚不存在。本轮没有跨 SQLite 与文件系统的原子事务保证。
- 显式核实只查询原操作，不自动恢复写入。重复请求不得绕过未决操作；同一实例防重不代替跨进程持久幂等。

## 尚未实现

端口必须由后续真实实现保证可信暂存身份、不可变字节、原生媒体校验、排他发布、原子提交和可靠核实。失败后的暂存、孤立发布文件及预留记录不能据不确定回执随意删除，恢复与清理仍需持久日志及精确身份核实。

目标目录策略、本地导入执行的产品语义、数据库升级及 V7 备份兼容仍待配套设计。本轮没有选择用户目录、导入文件、播放视频或修改完成状态，也没有声称 Windows 编码／重解析点／文件锁验收通过。

## 本轮验证

新增5项注入端口回归：取消零调用、预留先于暂存、同一字节解码证据、失效意图不发布、重复请求／处理中互斥、发布与清理不确定、提交回执错配以及提交成功但回执丢失后只读核实。全量311/311（0失败、0跳过）、类型检查、构建、差异检查通过。提交保留测试只用内存模拟记录，不是生产SQLite或真实文件原子性测试。
