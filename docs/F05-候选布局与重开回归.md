# F05 候选布局与重开回归

V1.19 云端增量，基于 3d79612。对照界面文档的叙事顺序、手工节点位置、来源连线及重开恢复要求。只用合成工作区和 SQLite；不调用分镜服务或操作真实账号。

## 审查范围

检查候选镜头进入画布时与已有手工节点的关系，以及镜头重排／删除后提示词导航身份、首尾来源连线、候选来源快照、坐标和内容是否保持一致。画布显示顺序不能替代镜头数组的叙事顺序，布局操作不应改写正文或历史输入。

## 已复现问题及最小修复

在无镜头但已有资产的工作区中，把资产手动放到 `(440, 80)`，再采用新增分镜候选。旧采用路径直接写入候选默认坐标，新镜头也位于 `(440, 80)`，与资产重叠；手动新增镜头则已有避让逻辑。

采用路径现在复用 `placeAddedNodes`，同时传入当前已测量节点尺寸，只为新增镜头及提示词节点寻找空位，保留所有旧节点的手工／派生坐标。不改候选内容、ID、叙事顺序、批准或保存条件，不自动整理整个画布。

## 验证与限制

新增 3 项合成回归：重叠旧行为确证及修后避让／旧坐标不变；重排和删除后的首尾来源边变化、角色导航及候选原始来源保持；长提示词及手工位置在重排、新增、实际 SQLite 保存关闭重开后保持，旧文本标为待更新而不覆盖历史。全量 `npm test` 262/262（0 失败、0 跳过）、`npm run build`（含类型检查）和 `git diff --check` 通过。独立复审无阻断，独立纯测试 2/2 通过；数据库测试由主实现线程执行。纯函数／仓库保存重开回归不等于实际 ReactFlow、面板点击、窗口尺寸和 Windows 桌面验收。

静态审查另见：当前“下一步”更新选中项／面板，没有显式 fitView 或 setCenter；文档所述“定位相关内容”若要求将视口外节点移入视野，仍是待补的交互验收点。本轮不引入新的视口移动行为，不宣称这项已完成。
