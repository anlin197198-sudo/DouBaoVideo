# F17 暂存字节独占归档接缝

## 已实现的可执行边界

主进程内部 `archiveStagedVideo` 接收可信暂存读取器（固定摘要／字节数、单次流）、显式受信本地归档目录、稳定命名身份、同步当前归属检查及取消信号。它实际使用既有独占写入器，逐块读取并复核完整摘要／长度，不把整片聚合进内存；源文件不修改。

独占写入器新增可选同步 `beforePublish`。入口及最后一次临时文件检查完成之后、调用硬链接发布之前检查，必须明确返回 true；false、抛错或非同步 true 都不开始发布，并清理自己创建的暂存。仅有短小、可信的同步归属检查适用于此端口。

这是最终发布调用前的一次检查，不是跨数据库与操作系统的原子锁。硬链接调用已经开始后发生的取消不能倒推成“未写入”。结果保留真实 `published`、`published-cleanup-failed`、`not-published` 或 `publication-uncertain` 回执，并独立报告返回时归属是否仍有效。已发布文件永不作为取消回滚删除；不能自动重试。

## 为什么尚未直接放进现有 handoff

现有 `SnapshotHandoff.consume` 明确是只读消费者，并会与取消竞争提前返回。把文件发布放进去，可能发生外层已报告拒绝、后台却完成发布的情况。本轮没有修改或违反该契约，也没有宣称完整导入已接好。

新归档边界不抢先用取消结束写入 promise，而是等待写入器结算。调用者必须在此期间保持暂存及归属生命周期，随后再处理独立回执。后续产品接线需要一个明确等待副作用结算、保存／核对回执的交接协议与真实版本／导入事务；不是把此函数塞进当前只读回调即可。

## 失败与未完成项

取消发生在取得来源之前时不打开来源；取得后变旧会关闭自己取得的读取器，不发布。若写入器返回前出现未知异常而没有回执，报告 `receipt-unconfirmed`，不冒称未发布。读取器清理结果和目标文件回执分别保留。

目录只由主进程显式提供，不接受 renderer 路径。本模块不创建数据库行、执行记录或账户操作，不提供 UI，不是媒体解码证明；现有命名中的 executionId 仍只由可信调用者提供，本轮测试全部使用合成身份，没有借用真实执行。归档目录策略、导入事务、重启恢复与成片播放仍待产品接线。

## 本轮验证

使用临时目录、仓库合成 MP4、真实 intake／暂存及真实独占写入器，验证完整字节一致、源文件保持不变、同目标拒绝覆盖、取消前不打开、取得期间取消、硬链接已完成后的迟到取消／回执丢失、目标被外部移走时保留不确定、临时清理失败仍保存已发布回执。没有运行原生播放器或用户素材。

新增 7 项归档／发布门槛回归通过；全量 396/396（0 失败、0 跳过）、类型检查、构建及差异检查通过。错误的运行时异步检查函数被拒绝且拒绝结果被吸收，不把 Promise 当授权。审查没有发现额外阻断；未进行原生媒体验收。
