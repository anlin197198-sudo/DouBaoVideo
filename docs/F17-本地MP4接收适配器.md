# F17 本地 MP4 接收适配器（主进程内部）

新增真正读取本地选择文件的内部步骤，不再只模拟日志状态。仅接受可信主进程调用方已经明确确认的路径与选择时文件身份快照；没有 renderer 路径接口、原生选择器接线、导入按钮或数据库迁移。

## 接收与暂存输入

- 固定只读普通文件句柄，比对选择时的身份／大小／时间和打开后的状态，拒绝链接、替换、截断或读取期间变化。绝不修改源文件。
- 使用最多64 KiB块计算精确字节数及 SHA-256，受现有8 GiB字节上限约束，不缓存整个视频。此上限不是耗时承诺。
- 实际检查顶层 MP4 box 的尺寸／边界、受支持品牌和非空 moov／mdat。当前品牌仅接受 isom、iso2、mp41、mp42、avc1 中任一种；ftyp负载最多4096字节、顶层box最多10000个，其他文件保守拒绝，不声称兼容全部MP4。只说明通过当前有限容器结构规则；不解析或认证轨道、编码器、时长，不证明可播放。
- 返回冻结的字节证据与一次性流；证据明确 decoded=false，不含原路径。流从同一句柄读取，交给既有独占写入器时再核对摘要／长度；源内容变化不得成为成功发布。
- 正常结束、显式关闭、取消、流错误／提前结束须关闭句柄。不消费流的调用方仍须显式关闭候选。

## 仍缺的生产集成

这一步不产生协调器要求的“已真实解码”证据，不能把结构检查结果转成 verified decoder，也不创建成片或完成任务。后续必须补同字节实际媒体解码、受管暂存／目录策略、持久登记及事务一致性，才能连接产品导入和播放器。

完整接收哈希加暂存流意味着至少两次全文件读取，成本随文件长度增加；未进行大文件性能或 Windows 原生验收。固定句柄和元数据／摘要检查不是对恶意同用户持续原地修改的操作系统沙箱；通用 Node 链接检查也不等于完整 Windows reparse 安全证明。

测试只使用自建容器结构与合成字节，不使用用户素材、不访问网络或媒体服务，不声称合成容器可被解码。

## 本轮验证

新增3项多场景合成回归，覆盖普通／扩展box、非法品牌和高位字节、截断／超数量／尺寸、选择后替换及链接、源流中途改写、提前return、idle／active abort、未消费关闭和真实独占写入精确读回。全量324/324（0失败、0跳过）、类型检查、构建、差异检查通过；独立静态审查无阻断。源字节不被写入器修改，变化源不产生成功发布。
