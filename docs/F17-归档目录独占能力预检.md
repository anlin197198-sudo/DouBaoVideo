# F17 归档目录的独占保存预检

在较早 F17 源码恢复版上重新加入安全目录预检。此预检只在主进程内部命令中运行：操作者在原生对话框明确确认已有私有本机保存目录后、建立解码宿主或暂存 MP4 前。普通应用成片页仍不传入导入能力；受信路由仍默认关闭。没有新增系统权限、替代命令、自动重试或 Windows 验收声明。

1. 在同一实际确认目录独占打开两个随机临时测试名，以不同固定短文本写入并同步，确认常规文件身份。不会读取原有文件或覆盖数据。
2. 尝试把 A 的硬链接建立到已有 B 上，要求收到 `EEXIST`、且两个原文件身份和内容不变。仅删除已证明属于预检的 B，再试空目标；必须收到成功确认并验证两名同一文件身份、链接数与字节内容。没有普通 rename/覆盖后备。
3. 只清理能证明归属的测试名，遇到替换／清理失败保留不确定现场，不删除外来对象。确认目录、窗口、任务修订或取消状态变化时停止；清理不能确认的状态不被取消掩盖。返回成功也不为稍后的独占归档写入提供保证，原写入保护继续生效。
4. 经确认的权限或不支持错误显示固定的“不支持安全的独占保存”，不发送本地路径，不启动解码、暂存、成片保存或 SQLite 变更。失去成功回执但观察到测试链接并非通过；若能确认清理，仍拒绝继续。预检不等于有任何真实成片发布结果。

目录必须由主机独占使用且受信。双重身份检查不承诺抵御能同时替换目录与文件的同用户程序；一般支持不代表所有 Windows 文件系统能通过。这里的 `EPERM`/`EACCES` 都是云端注入的合成错误，未接触 Windows、真实文件／账号或 Electron。

新增测试覆盖：云端真实同目录硬链接，已存在目标拒绝覆盖，权限拒绝，回执丢失，取消／所有权过期，清理拒绝和外来文件保留；真实本地命令及 SQLite 测试用例验证固定文本及在拒绝时不创建宿主、暂存或登记。

云端定向 **17/17**、全量 **467/467**（零失败、零跳过）、双端类型检查、生产构建与 diffcheck 通过。
