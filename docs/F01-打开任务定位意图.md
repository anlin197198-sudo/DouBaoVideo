# F01／F05 打开任务定位意图（未接 UI）

V1.19 云端增量，基于 19c42aa。

## 审查结论

界面设计中“制作中 → 打开画布，定位相应节点”属于任务队列的状态主操作。当前周计划的任务标题、打开画布、历史日期和归档打开共用同一个普通入口，没有区分“恢复保留画布”与“继续当前步骤”的导航意图，队列对应入口尚未接入。

直接在 TaskCanvas 挂载时自动定位会改变普通重开应恢复的视口，也可能让历史／归档查看跳到其它节点。因此本轮不改变周计划、App 或 TaskCanvas 的打开、挂载和保存行为，不新增按钮。

## 内部边界

仅对显式“打开当前本地步骤”创建一次性意图，复用 `nextLocalStep` 而不另立步骤规则；绑定任务、修订和当前工作区／风格。普通恢复不创建定位意图；内容或身份变化、未保存及忙碌状态不能让过期意图移动视口。

只返回存在的画布节点目标。不把“添加镜头”或“整理资产”这类步骤变成自动写入或弹出新流程，也不发送请求、修改布局、保存视口或确认素材。

## 后续接入前提

先在已批准的任务队列状态操作中明确区分“继续当前步骤”与“恢复画布”，再通过可核实的单次挂载生命周期消费意图。接入必须处理节点尚未测量、关闭／切换、迟到响应、未保存内容和覆盖层；不得以重复 effect 自动定位。真实 UI 接入及 Windows 运行验收尚未完成。

## 验证

新增 3 项纯回归：普通打开和非节点步骤不创建意图；显式步骤目标只消费一次及取消；任务／修订／内容／布局变化、忙碌或未保存状态拒绝且不能恢复旧意图。全量 `npm test` 269/269（0 失败、0 跳过）、`npm run build`（含类型检查）及 `git diff --check` 通过。独立复审无阻断，纯测试 3/3 通过。本轮没有用户可见的新定位入口，不能据内部契约宣称列表打开定位已完成。
