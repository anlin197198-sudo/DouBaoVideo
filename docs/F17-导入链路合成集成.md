# F17 导入链路合成集成（未接产品）

把真实内部导入协调器、独立 SQLite 意图日志与独占字节写入器组合到同一个测试夹具中，验证文件发布与数据库状态的先后关系。不新增生产端口、工作区迁移或用户界面。

## 本轮范围

- 仅使用测试自建字节和临时目录。解码证据由夹具模拟，不宣称字节是可播放 MP4，也不执行真实解码。
- 原型日志先预留，并在调用真正文件写入器前提交“可能已发布”；文件以真实独占发布实现写入，比较实际摘要和文件数量。
- 正常提交后关闭并重开 SQLite，核对同一请求／回执；重复执行不再次发布文件或插入记录。
- 元数据提交成功但回执丢失时，保留已提交记录与文件，通过显式只读核实确认，不重复写入。
- 文件发布后回执丢失时，重开后仍是未决的“可能已发布”，不将缺失回执当作失败重写，也不自动补记确认。

## 不能据此推出的保证

数据库关闭重开不等于完整进程崩溃恢复。测试夹具仍持有原始不可变阶段／模拟解码证据；独立日志只封存简化回执，不足以在真实进程重启后恢复全部协调器阶段证据。因此没有构造生产恢复适配器，也不自动把孤立文件升级为已验证媒体。

只检查指定临时目录的字节和原型日志，没有源路径或媒体字节入库。未接现有 `films`、执行状态或任务完成状态。需要后续真正的持续排他、媒体验证和登记持久化，才能连接产品导入与播放器。没有 Windows、真实媒体、断电或多进程故障验收。

文件命名器的 executionId 字段在夹具中仅填入合成预留 UUID，不创建或借用真实执行记录；生产导入身份与命名规则仍须正式定义。

新增3项集成回归，全量318/318（0失败、0跳过）、类型检查、构建及差异检查通过。测试确认每场景只调用一次写入器、只保留一个输出文件和一条日志，重开后字节不变；未决发布没有提交回执，原型版本头不前进。
