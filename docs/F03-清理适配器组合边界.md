# F03 清理适配器组合边界

V1.19 云端增量，基于 e34dcf4。依据 ACC 01：移除清理对应本机会话，但保留原账号、任务及成片引用。本轮只组合已有租约、受管理窗口关闭及显式清理端口；没有产品入口、真实 Electron 清理器或账号操作。

## 组合顺序与失败处理

内部协调器接收完整账号／操作／租约身份，核对当前待清理状态，关闭并核验本管理器拥有的该账号窗口，再通过显式注入端口请求清理。清理回执必须绑定相同租约且明确验证会话清理；最终再次核对租约后，才可返回现有工作流所需的成功证据。关窗本身不能充当清理回执。

任一步失败或回执失配，不得把账号标记为成功移除。现有工作流保持禁用及待处理，按所属租约释放失败操作；历史身份与引用保留。完成提交结果不明仍遵循既有“不回退已移除状态”规则。

## 尚未实现的真实保障

- 同步 SQLite 栅栏只能包围短同步操作。清理前后检查不能锁住跨 `await` 的清理，也不能撤销迟到的磁盘删除。
- 未来清理端口必须在每个破坏性操作期间真正持有该账号排他权，确认全会话、网络、service worker 及其它句柄静止；不是只关闭一个窗口。
- 端口无论返回或抛错，均必须先停止全部底层清理活动。否则工作流释放租约后，旧后台任务仍可能影响重试，这是不允许的。
- 当前端口只有合成测试实现；接口契约不是操作系统级独占或清理能力。没有 UI／IPC 接线、真实分区清理、凭据删除、平台调用或崩溃残留租约恢复。

F03 仍为部分完成，不宣称真实会话或凭据已清除。真实实现必须先完成上述适配器保障，再按用户明确确认及 Windows 验收要求开放入口。
