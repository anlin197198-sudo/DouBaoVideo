# F17 私有首帧宿主组合（未在应用入口启用）

## 解决实际归属循环

准备器原本先为传入 owner 签发暂存能力，再调用原生宿主；而窗口工厂原本创建时才产生 owner。两者不能通过把用户窗口身份冒充私有窗口来连接。

现在先 `reservePrivateVideoProbeWindow` 创建唯一内存会话及专用沙箱窗口，获得真实 webContents ID 和全新文档身份，再为该 owner 暂存并签发能力。预留最长 15 秒且自动清理；随后 `loadProbe` 只允许一次固定文档加载，安装失败也不能重试该文档。旧一次性工厂保留兼容。

`createPrivateVideoFirstFrameHost` 先验证打包资源清单，再预留窗口。它提供固定 owner、绑定该窗口的能力注册表，以及只接收规范能力 URL、对应可信 owner 和取消信号的 probe。异主／异文档／失效能力被拒绝，不改签令牌。页面与媒体共用一个私有 handler，资源由精确哈希清单加载器提供。

## 固定结果读取

宿主只在该窗口执行一个固定、主进程编写的结果属性读取表达式，不接受任意脚本、选择器、页面地址或磁盘路径。每次读取前后验证能力、窗口及文档；未返回结果时短间隔轮询，最多 8 秒。取消可结束等待中的读取，不接受迟到结果。页面报告仍交给准备器严格检查，且必须真实取得暂存字节才可能成为首帧观察结果。

这不证明整片可解码、可播放，不会注册成片或发布媒体。合成测试中的首帧报告由模拟 Electron 返回，不是原生解码证据。

## 停止与文件清理顺序

`createPrivateVideoDecodeInspector` 组合预留、暂存、令牌、固定页、结果读取及停止。准备器在验证结果后撤销能力并取消，然后可选地等待可信 `stopProbe(owner)` 的明确成功，默认限时 1000ms。只有成功才调用暂存的 discard（其本身等待取得中的句柄并关闭所有已归属读取句柄）及删除自身暂存文件。

停止失败、超时或未知时保留暂存，返回 `cleanup-unconfirmed`，不会因迟到的停止成功而自动删除；仍尝试关闭原始 intake。不能把窗口销毁当作所有 Chromium 网络状态的证明。没有 stopProbe 的既有注入式测试路径保持原行为，未来原生调用必须使用该组合或同等有序关闭契约。

## 已验证与未验证

新增窗口两阶段 2 项、停止清理 3 项和真实模块组合 3 项合成回归，覆盖 owner 在令牌之前建立、单 handler 固定页与媒体读取、固定结果脚本、取消挂起读取、未确认销毁保留暂存、闲置过期和不可重复加载。全量 382/382（0 失败、0 跳过）、类型检查、构建及差异检查通过。实际构建后的资源清单／摘要被生产加载器接受，固定 HTML 返回 200。

未启用应用入口、全局 scheme privileges、默认 Session 或按钮；没有启动 Electron 或 Windows 窗口。仍需原生协议权限资格审查、隐藏页面是否可产生首帧回调的真实验证、实际编解码器兼容及完整播放器验收。不要用这些纯／合成测试把 F17 标成已完成。
