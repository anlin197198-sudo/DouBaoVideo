# F04 归档与排期边界

V1.19 云端验证切片，基于 066f241。本轮不实现重新加入排期，也不增加派发或执行能力。

## 文档结论

产品与界面文档明确：编辑日期／数量先预览；增加数量补建任务，减少数量明确选择未提交任务移出，保留制作内容；已有提交／执行历史不改。开发文档把「归档任务重新加入排期」列为待办，但没有定义以下规则：

- 目标日期已满：拒绝、替换哪个未提交任务，还是改变每日数量（是否连带其余六天）？
- 可否改到原日期以外、当前七天以外或另一个计划？
- 恢复时沿用任务旧时间还是继承当前计划时间？

这些选择影响用户制作内容和每日计划数量，不能从“重新加入”自行推定。本轮保持现行产品规则，不偷偷复用或重新激活归档任务。后续需先明确规则，再做独立预览与用户确认。

## 现行可依赖行为

- 归档只移出排期，不删除身份、制作内容或已保存剧本／提示词历史，归档内容仍可编辑。
- 增加数量或日期范围返回时补建新的空任务，采用新的任务ID与未占用序号，不把原归档稿当成空位覆盖或自动重新排期。
- 编辑预览绑定计划、任务及执行／成片记录。确认前相关状态变化应拒绝旧预览，并要求重新预览。
- 有执行／成片记录或不属于明确可编辑状态的任务保持锁定；编辑计划不能伪造历史输入或触发执行。
- 正常应用与请求回执同事务；同一请求重放不会再补建一批任务。归档及新任务数量不替代真实调度的运行验收。

## 本轮验证

仅云端合成数据。新增 3 项集中回归：①归档后编辑两类正文、补建／跨日期返回、请求重放及数据库重开保留身份和全部历史；②归档内容、未知状态、执行、成片在预览后变化，旧预览逐项拒绝，计划／任务／历史／回执均无额外写入；③锁定任务与执行／成片记录在改时后逐字不变，风格及继承说明变更拒绝。全量 `npm test` **124/124 通过，0 失败、0 跳过**；`npm run build`（含类型检查）及差异检查通过。没有发现需要修改现有生产逻辑的缺陷。无新增产品入口、数据迁移、重新排期规则或外部调用。Windows/UI未验收。
